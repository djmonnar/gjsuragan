# 출퇴근 태블릿과 관리자 예약 관리

태블릿은 돌담명가의 오늘 네이버예약과 직접 등록한 예약을 자동으로 표시한다. 최초 로딩, 화면 복귀, 인터넷 재연결, 한국 날짜 변경, 이후 **5분마다** 조회한다. 오너비스타의 기존 네이버 수집 주기는 변경하지 않는다. 예약 API는 출퇴근 API와 독립되어 있다.

## 사용 방법

- 태블릿 `attendance.html`: 오늘 예약의 이름·시간·인원·메뉴·좌석·상태와 등록 경로를 확인한다.
- **예약 등록**: 이름, 날짜, 시간, 메뉴, 인원(기본 2명), 좌석(선택)을 입력한다. 메뉴는 기존 목록에서 선택하거나 직접 적을 수 있다.
- 직접 등록은 오너비스타의 같은 매장에 저장된다. 네이버에 예약을 생성하거나 고객에게 메시지를 보내지는 않는다. 예약 수정·취소는 오너비스타에서 한다.
- `staff-admin.html#reservations`: 별도 매장 관리 페이지에서 기존 관리자 비밀번호로 로그인 후 날짜별 예약 조회와 간편 등록을 할 수 있다. 직원 등록·수정·삭제, 근태 캘린더, 시급 기본급 정산은 **직원·근태** 탭을 이용한다.
- 확정·신청·이용완료를 방문 건수/인원에 합산한다. 취소·노쇼는 태블릿에서 별도 접힌 목록에 표시한다.
- 수집 전, 연결 미설정, 조회 실패, 실제 예약 없음은 구분한다. 수집 전에도 직접 등록한 예약은 보인다. 일시 실패하면 같은 날짜의 마지막 목록과 경고를 표시한다. 자정 또는 권한 거절 시 태블릿의 기존 목록을 지운다.

## 서버 연결

태블릿 또는 Firebase 관리자 인증 → `attendanceBookingsApi` → 오너비스타 전용 API → 기존 예약 저장소.

- 태블릿 조회는 `/api/integrations/attendance/today`로 오늘만 조회한다.
- 관리자 조회는 `/api/integrations/attendance/reservations?date=YYYY-MM-DD`로 선택 날짜를 조회한다.
- 등록은 두 화면 모두 `/api/integrations/attendance/reservations`로 전달한다. 매장과 요청자 ID는 서버가 지정한다.
- 요청 UUID와 기기/관리자 ID로 중복 등록을 막는다. 응답 지연 시 같은 입력으로 재시도하면 기존 결과를 반환한다. 직접 등록 이름은 기존 오너비스타 암호화 저장 방식을 사용한다.
- 전화번호, 결제금액, 요청사항, 내부 메모, 알레르기 답변은 태블릿/관리자 피드로 내보내지 않는다. 연결키는 브라우저에 전달하지 않는다.
- 기기 인증은 최대 20초의 서버 메모리 캐시를 읽기 전에도 매 요청 확인한다. 예약 응답은 HTTP 캐시나 브라우저 저장소에 보관하지 않는다.

## 배포 설정

1. 오너비스타 조직명과 네이버예약 매장 연결을 확인한다. 플레이스 ID를 조직 ID 대신 쓰지 않는다.
2. 32바이트 이상의 임의 연결키를 만든다. 소스·채팅·로그에는 기록하지 않는다.
3. 오너비스타 Production 환경 변수 `ATTENDANCE_BOOKINGS_ORGANIZATION_ID`에 확인한 조직 ID, `ATTENDANCE_BOOKINGS_TOKEN_SHA256`에 연결키 SHA-256 해시를 설정한다.
4. 궁중수라간 Firebase Secret Manager `OWNERVISTA_BOOKINGS_TOKEN`에 같은 키 원문을 설정한다. `attendanceBookingsApi`에만 바인딩한다.
5. 오너비스타 API를 배포한 뒤 궁중수라간 `attendanceApi`, `attendanceBookingsApi`, Firestore Rules, GitHub Pages를 배포한다. 기존 함수 전체를 재배포할 필요는 없다.

연결 해제는 오너비스타 해시 삭제/교체 또는 기존 연동 비활성화로 한다. 특정 태블릿은 별도 매장 관리 페이지의 태블릿 관리에서 해제한다. 예약 연동 대상은 돌담명가이며, 직원의 근무 매장 선택은 예약의 매장 연결을 변경하지 않는다.

## 로컬 검증

`functions/scripts/preview-attendance.js`는 Emulator와 가상 예약만 사용한다. `/preview-bookings-scenario?state=ready`에 POST하면 상태를 전환할 수 있다. 지원 상태: `ready`, `error`, `empty`, `waiting`, `unconfigured`, `stale`.

단위 테스트는 인증·필드 제한·등록 검증·중복 요청·5분 갱신을 확인한다. 오너비스타 Emulator 테스트는 실제 저장·암호화·날짜 합계·중복 방지·좌석 수정·삭제 후 재시도를 확인한다. 브라우저에서는 태블릿 등록 후 관리자 조회까지 검증한다.
